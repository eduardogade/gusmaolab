# Known limitations

Recorded in P01 and updated in P02, P03, P04 and P05 (2026-11-10), and in P06, P07, P08 and P09 (2026-11-11).

| ID | Limitation |
| --- | --- |
| KL-01 | Bearnard images are not in Git, because `brand/bearnard/` is gitignored. Only the external backup and `assets/bearnard/SHA256SUMS` protect them. The backup is a snapshot from 2026-11-10 13:23, so anything changed after that is unprotected. |
| KL-02 | The private workspace folders `_books/`, `_papers/`, `_references/` and `_reports/` are gitignored and protected only by the external backup. They hold private material and must never be committed to this public repository. |
| KL-03 | Git cannot track empty folders. `backup/`, `releases/`, `resources/`, `viz/` and `_logo/` exist only on disk and in the backup. |
| KL-04 | The legacy site no longer builds from the root. Building it from inside `_backup/pelican-legacy/` was not tested, and Pelican is not installed in the default shell. |
| KL-05 | Much of the legacy content is empty: 4 blog posts, all 10 Portuguese pages, all 6 data files, and every tracked file in `cv/`, `publications/`, `scripts/`, `data/`, `hyperglam/` and the GusmaoLab theme templates. |
| KL-06 | The local Node.js is v26.12.0. The 26 line has been LTS since v26.13.0 (2026-10-28), but this build predates that and lacks the v26.12.1 security release (2026-10-21). Update to the latest 26.x release; P02 did not change the machine. |
| KL-07 | The pre-commit hook runs from the micromamba environment `web`. Commits will fail if that environment is removed. |
| KL-08 | Two obsolete recruiter-era files, `content/extra/conversion_logix_partial_delivery_5b.zip` and `content/static/ResponseToFelipe/questionnaire.md`, were removed from the working branch in P02 after their backup copies were confirmed. They remain in the public Git history and possibly on the deployed legacy site. Follow-up: ISSUE-0003 (open). |
| KL-09 | The header of `.pre-commit-config.yaml` says no hooks run, but six hooks are active (ISSUE-0001). |
| KL-10 | The backup ZIP was made with macOS Finder: it includes 9,639 `__MACOSX/` metadata entries and one symlink (`node_modules/.bin/prettier`). To restore, extract it outside the repository and ignore `__MACOSX/`. |
| KL-11 | The root `.gitignore` has Python-template patterns, such as `lib/`, `build/`, `env/` and `downloads/`, that match folders at any depth. A future `src/lib/` would be silently ignored; P04 hit exactly this and used `src/navigation/` instead. Check new folders with `git check-ignore -v <path>`. |
| KL-12 | Prettier does not format `.astro` files, because `prettier-plugin-astro` is not installed (D-021). |
| KL-13 | Astro's optional peer dependency `@astrojs/markdown-remark` is not installed. Markdown pages may need it; not verified in P02. |
| KL-14 | Astro's telemetry setting was not changed. P02 ran every Astro command with `ASTRO_TELEMETRY_DISABLED=1`. To opt out permanently, run `npx astro telemetry disable`. |
| KL-15 | The typefaces are system fonts. Seravek, Iowan Old Style, Superclarendon and STIX Two Math ship with macOS, and other platforms fall back to relatives such as Calibri, Palatino, Bookman or Georgia. Only macOS rendering was inspected. Chrome does not support `ui-monospace`, so code uses Menlo there. |
| KL-16 | The flannel is generated with CSS gradients. It can look more synthetic than a real textile, and its repeat is a fixed 8.25rem. No moiré was seen in Chromium at standard density; high-density screens and other browsers were not inspected. |
| KL-17 | The `prefers-contrast: more`, `forced-colors: active` and print fallbacks exist in CSS but were not checked visually. Screen readers were not tested. The contrast test covers opaque pairings only, not text over the flannel or translucent layers. |
| KL-18 | Astro's HTML compression drops the whitespace where a line in an `.astro` template ends just before an inline element, gluing the words together. Keep such text and its inline element on one line, or add `{" "}`. |
| KL-19 | The P03 visual review used Chromium-based browsers only: the Claude desktop app's browser (Chromium 152) and headless Chrome 157, on macOS 26.6.2. Safari and Firefox were not inspected. |
| KL-20 | Folder rows can be wider than their folder (P05); since P08 that is the responsive strategy, not a fallback (D-064). CV's row, with its Overview tab, needs about 1,300 px, more than the shell allows at any width, so it always scrolls inside its strip and opens at its selected tab. The top-level tabs fit from 1280 px up in Chromium on macOS (and, since P08, at every wider width too): the twelve of P04–P09 needed 1,145 px, with 11–17 px to spare; the eleven since P09-A01 need about 1,012 px of the 1,171 px strip at 1280 px. Wider fallback fonts elsewhere may still make that row scroll at 1280 px. "Outreach / Public Engagement" wraps inside its tab, which at 320 px is wider than the clear middle of its row. |
| KL-21 | The folder geometry relies on CSS trigonometric functions (`atan2()`, `sin()`, `cos()`), supported since Chrome 111, Safari 15.4 and Firefox 108. Without them, tabs would fall back to plain rounded rectangles, and the seam between a selected tab and its folder would show. Opening a scrolling row at its selected tab uses `scroll-initial-target` in Chromium and, since P08, `src/scripts/folder-rows.ts` elsewhere; without both, rows open at their start. Row scrollbars are hidden, and there are no scroll buttons (D-064), so a mouse without horizontal scrolling must use Shift + wheel or the keyboard. |
| KL-22 | The P05 folder review used Chromium-based browsers on macOS only: the desktop app's browser (Chromium 152) and headless Chrome 157. Safari, Firefox, Windows and Linux fonts, `forced-colors: active` (a fallback exists), screen readers and touch devices were not inspected. Focus was checked only on a tab label turned into a link for the test, because the tabs are not links until P06. |
| KL-23 | The local preview server on macOS serves `/CV/` as `/cv/` (status 200, the CV page), because the macOS file system ignores case. The navigation model treats `/CV/` as unknown, and the static host is expected to be case-sensitive, which was not tested (nothing is deployed). Do not rely on a local check of letter case. |
| KL-24 | There is no designed 404 page (P06). An unknown URL has no file, so the host answers with its own 404: Astro's plain page locally, and GitHub Pages' default page once deployed. A page using `resolve()`'s `context` belongs with the content states (P17). |
| KL-25 | There is no skip link (P06). Keyboard users reach the content after the tab links: 11 on the global row (12 before P09-A01), up to 9 in a second row and, later, a third row. The rows are navigation landmarks and the content is `<main>`, so screen-reader users can jump between them. Since P07, keyboard focus on an unopened folder with children also opens its preview, whose links come next in the order; a closed preview's links are skipped, so the path to the content is no longer than in P06 unless a visitor enters a preview. |
| KL-26 | The P06 navigation review used Chromium only: the desktop app's browser and headless Chrome 157, on macOS, at 1440, 1280, 768 and 390 px. Link navigation, Back, Forward and reload were tried there only. Safari, Firefox, touch devices, `forced-colors: active` and screen readers were not tested; accessible names were read from Chrome's computed accessibility tree (for example "Overview of CV") and `aria-current` values from the built HTML, not by listening. |
| KL-27 | Folder previews need the Popover API (`popover`, `showPopover()`), available since Chrome 114, Safari 17 and Firefox 125, and `:has()` for the previewed tab's hover color. Without the Popover API there are no previews; tabs work as plain links, and every destination is still on its folder's page. The script is the site's only JavaScript; a visitor without JavaScript gets the same plain links. |
| KL-28 | The P07 review used Chromium only: headless Chrome 157 (`npm run test:browser` and screenshots) and the desktop app's browser, on macOS, at 1440, 1280, 1024, 768 and 390 px. Touch was emulated through the DevTools protocol, not tried on a phone or tablet; Safari, Firefox, `forced-colors: active` and screen readers were not tested. Keyboard behaviour was checked with synthesised key events and the focused element, not by listening. |
| KL-29 | A preview is placed when it opens and again on scroll and resize. If the page's layout changes while one is open for another reason (a late web font, say; none is loaded today), the card may sit a few pixels off until the next scroll or until it reopens. |
| KL-30 | Each folder page carries its previews' markup and the inlined script (2.75 KB in P07, 3.8 KB with P08's row module): `dist/` grew from 381,438 bytes (P06) to 752,130 (P07) and 811,331 (P08, with study case I), most of it the folder study's twelve stacks. The smoke test's generous 1 MB ceiling still holds, but real content will need it revisited (P10 onwards). Since P09 the ceiling is three (D-074): the site's own files, the design studies and the illustrations. After P09-A01, which removed External, the candidate stylesheet and the environments study: 628,105 bytes of 1 MB, 210,237 bytes of 600 KB and 242,020 bytes of 600 KB (651,442, 304,063 and 242,020 at the end of P09). |
| KL-31 | Since P08 the paper scrolls sideways (`overflow-x: auto`) as a last resort for content too wide for it (D-068). That makes it a scroll container: a future `position: sticky` element inside the paper, such as a table of contents, would stick within the paper rather than the window. Revisit if one is added. |
| KL-32 | The P08 review used Chromium only: headless Chrome 157 (`npm run test:browser` and screenshots at 320, 360, 390, 430, 768, 1024, 1280, 1440, 1920 and 2560 px) and the desktop app's browser at its 375 px mobile preset. Touch, coarse pointers, zoom and large text were emulated. **Real phones and tablets, Safari (including iOS), Firefox and screen readers were not tested and await the owner's verification.** The script that opens rows in browsers without `scroll-initial-target` was tested in Chromium with that property removed, not in Safari or Firefox themselves. |
| KL-33 | Browsers scroll a focused tab into its row but ignore the row's scroll padding, so without JavaScript a focused tab, or its focus ring, can stop under an edge fade (in Chromium, up to 2 px past the edge). The tab is still focused and usable; `folder-rows.ts` corrects the position when JavaScript runs (D-066). |
| KL-34 | While the 140 ms cross-fade between folder pages plays (P09), the browser sends input to the page root, so a click or tap in that moment is ignored. Visitors rarely act that fast; reduced motion has no fade and no such moment. |
| KL-35 | In headless Chrome 157, about 1 cross-fade in 4 to 10 starts from a blank white snapshot of the old page, which then fades out: a flash. A physical Android phone, Safari and Firefox were not tested (ISSUE-0004). |

The next change to either script will make Astro emit it as a cached file instead, which the smoke test and NAV-031 will flag, so that change needs a decision: accept the file (one more request, smaller pages) or keep the code under the limit. |
