From Synthetic Signals to Reproducible Results

A miniature scientific tutorial: two invented signals, controlled noise, a few summary statistics, and what it takes for someone else to get the same numbers again. Everything is synthetic.

Prerequisites

  • Reading simple Python
  • Mean, standard deviation and the sine function

WarningSynthetic data

Every number and curve on this page is generated by a seeded random number generator inside the document. They are invented to teach a method; they are not measurements of anything, and no conclusion about biology follows from them.

Motivation and context

A result is reproducible when someone else, with the same code and the same inputs, obtains the same numbers (Peng 2011). It sounds like the minimum one could ask of a computed result, and it is surprisingly easy to lose: a random seed that was never fixed, a library that changed between two installs, a figure pasted from a session nobody remembers.

This tutorial is deliberately small. It builds two synthetic signals, adds noise whose size we control, compares a handful of summary statistics, and shows what must be recorded so that the same figure and the same table can be made again.1 The rules it follows are those collected by Sandve et al. (2013), in particular the rule to avoid manual steps and the rule to record every random seed.

What we will do

  1. Write the model of a noisy signal.
  2. Generate two signals from it with a fixed seed.
  3. Summarise each with a few statistics.
  4. Draw them and tabulate the summaries.
  5. Say what a reader needs in order to repeat all of it.

Reproducible setup

The computation uses only the Python standard library, so the environment is nearly empty: a Python interpreter, and the Jupyter packages that let Quarto run the cells. The project fixes both in files kept with the website’s source, and the site never runs the code when it is built.

npm run science:env -- check
npm run science:execute -- demo/demo-synthetic-signals
TipRun only when you mean to

science:execute is the one command that runs a document’s code. Rendering and building the site only read the results stored with the article, and stop with a message if those results no longer match the code.

The first cell fixes everything that could change the numbers: the seed, the number of samples and the parameters of both signals. Writing them in one place makes them easy to read, and easy to change on purpose.

import math
import random
import statistics

SEED = 20261114        # the only source of randomness in this document
SAMPLES = 160          # samples per signal
DURATION = 4.0         # seconds

# name: amplitude A, frequency f (Hz), phase (radians), noise standard deviation sigma
SIGNALS = {
    "A": dict(amplitude=1.0, frequency=1.0, phase=0.0, sigma=0.25),
    "B": dict(amplitude=0.6, frequency=1.0, phase=math.pi / 3, sigma=0.25),
}
print(f"seed {SEED}, {SAMPLES} samples over {DURATION} s")
seed 20261114, 160 samples over 4.0 s

A mathematical model

Each sample of a signal is a sine wave plus noise. At time tk=kΔtt_k = k\,\Delta t, with Δt=4/160=0.025\Delta t = 4/160 = 0.025 s, the observed value yky_k is given by Equation 1.

yk=Asin⁡(2πftk+φ)+εk,εk∼𝒩(0,σ2)(1) y_k = A\,\sin\!\left(2\pi f\,t_k + \varphi\right) + \varepsilon_k, \qquad \varepsilon_k \sim \mathcal{N}\!\left(0,\sigma^2\right) \qquad(1)

Here AA is the amplitude, ff the frequency, φ\varphi the phase, and the noise εk\varepsilon_k is drawn independently at every sample from a normal distribution with mean 00 and standard deviation σ\sigma. A natural question is how much of what we observe is signal and how much is noise. Taking the ratio of their average powers, a sine of amplitude AA has mean square A2/2A^2/2, and the noise has mean square σ2\sigma^2, so the signal-to-noise ratio is given by Equation 2.

SNR=A2/2σ2=A22σ2,SNRdB=10log⁡10SNR(2) \mathrm{SNR} = \frac{A^2/2}{\sigma^2} = \frac{A^2}{2\sigma^2}, \qquad \mathrm{SNR}_{\mathrm{dB}} = 10\,\log_{10}\mathrm{SNR} \qquad(2)

For our two signals Equation 2 predicts 8.08.0 (about 9.09.0 dB) for signal A, and 2.882.88 (about 4.64.6 dB) for signal B, because B has the smaller amplitude and the same noise.

Synthetic-data generation

Python’s random module provides uniform numbers, and we turn two of them into one normal number with the Box–Muller transform. A single generator, created from the seed, is the only source of randomness. Signals are generated one after the other, in a fixed order, so a signal’s noise does not depend on anything but the seed and its position in that order.

rng = random.Random(SEED)

def normal(sigma):
    """One draw from N(0, sigma^2), by the Box-Muller transform."""
    u1, u2 = 1.0 - rng.random(), rng.random()
    return sigma * math.sqrt(-2.0 * math.log(u1)) * math.cos(2.0 * math.pi * u2)

times = [k * DURATION / SAMPLES for k in range(SAMPLES)]
clean, observed = {}, {}
for name, p in SIGNALS.items():
    clean[name] = [p["amplitude"] * math.sin(2 * math.pi * p["frequency"] * t + p["phase"]) for t in times]
    observed[name] = [c + normal(p["sigma"]) for c in clean[name]]

for name in SIGNALS:
    head = ", ".join(f"{y:+.3f}" for y in observed[name][:4])
    print(f"signal {name}: {len(observed[name])} samples, first four values {head} ...")
signal A: 160 samples, first four values -0.086, -0.419, +0.439, +0.491 ...
signal B: 160 samples, first four values +0.778, +0.657, +0.798, +0.828 ...

The printed values are the first ones of each signal. Running the cell again prints exactly the same numbers, because the generator starts from the same seed every time.

Descriptive statistics

For each signal we compute the mean and the standard deviation of the observed values, and the root-mean-square (RMS) residual, which is the typical size of the noise that was actually added. The measured signal-to-noise ratio is the mean square of the clean signal divided by the mean square of the residual, to be compared with Equation 2.

stats = {}
for name, p in SIGNALS.items():
    y, c = observed[name], clean[name]
    residual = [a - b for a, b in zip(y, c)]
    ms_clean = statistics.fmean(v * v for v in c)
    ms_noise = statistics.fmean(r * r for r in residual)
    stats[name] = dict(
        mean=statistics.fmean(y),
        sd=statistics.stdev(y),
        rms=math.sqrt(ms_noise),
        snr_theory=10 * math.log10(p["amplitude"] ** 2 / (2 * p["sigma"] ** 2)),
        snr_measured=10 * math.log10(ms_clean / ms_noise),
    )
for name, s in stats.items():
    print(f"signal {name}: mean {s['mean']:+.3f}, sd {s['sd']:.3f}, rms residual {s['rms']:.3f}")
signal A: mean -0.022, sd 0.743, rms residual 0.271
signal B: mean -0.035, sd 0.495, rms residual 0.244

Reading the numbers

Both means are close to zero, as they should be for a sine wave sampled over whole periods. The standard deviation of signal A is larger than that of B because its amplitude is larger, even though the noise is equal. The RMS residuals are close to the chosen σ=0.25\sigma = 0.25 for both: the noise we asked for is the noise we got, up to the small fluctuations that any 160 random numbers have.

A table

Table 1 lists the statistics behind the figure. The last two columns compare the signal-to-noise ratio that Equation 2 predicts with the one measured in the generated samples.

from IPython.display import Markdown, display

head = "| Signal | Amplitude | Noise sigma | Mean | Standard deviation | RMS residual | SNR predicted (dB) | SNR measured (dB) |"
rows = [head, "|:---|---:|---:|---:|---:|---:|---:|---:|"]
for name, p in SIGNALS.items():
    s = stats[name]
    rows.append(
        f"| {name} | {p['amplitude']:.1f} | {p['sigma']:.2f} | {s['mean']:+.3f} | {s['sd']:.3f} | {s['rms']:.3f} | {s['snr_theory']:.2f} | {s['snr_measured']:.2f} |"
    )
display(Markdown("\n".join(rows)))

The predicted and measured values in Table 1 differ by less than one decibel. That difference is not an error of the method: it is the sampling variation of a 160-sample experiment, and it changes with the seed.

What a reader needs to repeat this

NoteThe short list

The seed, the code, the interpreter and the packages it ran with, and a command that runs it all without manual steps. Here: the seed is in the first cell, the code is this document, the environment is fixed by two small files, and one command recomputes everything.

Three things are worth keeping separate:

  • Same numbers. Because every random number comes from one seeded generator, rerunning the code gives the same values. This is what a fixed seed buys.
  • Same figure. The figure is produced by the code and not drawn by hand, so it follows the numbers. A redrawn figure would not.
  • Same tools. The numbers depend on the interpreter and the libraries. Recording their versions does not make a result right; it makes it possible to find out why two results differ.

A different seed would give slightly different statistics, and they would still agree with Equation 2. That is the other half of reproducibility: the conclusion should not depend on one lucky seed.

Practical conclusions

  1. Put the seed, the sizes and the parameters in one cell at the top.
  2. Use one random number generator, created once from the seed, and consume it in a fixed order.
  3. Make figures and tables from code, so that they cannot drift from the numbers.
  4. Run the document with one command, and keep the stored results with it.
  5. Treat agreement within sampling variation as agreement, and state how large that variation is.

References

Peng, Roger D. 2011. “Reproducible Research in Computational Science.” Science 334 (6060): 1226–27. https://doi.org/10.1126/science.1213847.
Sandve, Geir Kjetil, Anton Nekrutenko, James Taylor, and Eivind Hovig. 2013. “Ten Simple Rules for Reproducible Computational Research.” PLoS Computational Biology 9 (10): e1003285. https://doi.org/10.1371/journal.pcbi.1003285.
