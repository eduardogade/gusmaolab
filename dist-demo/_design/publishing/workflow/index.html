An Example of the GusmaoLab Publishing Workflow

This is a synthetic article, A Small Example, taken from its first draft to archive. Each block below is the real output of the real command, run on a throwaway copy of the project folder that was deleted afterwards. Nothing was written to the site's content, and nothing here was published.

  1. Create. The draft starts with status: draft, no date, and a slug fixed from the title.
  2. Check. Missing pieces are warnings while it is a draft.
  3. Break it. A misspelt field is an error, with the way to fix it.
  4. Repair and check again.
  5. Publish. First a dry run, which changes nothing; then the same command with --yes.
  6. Archive. The status changes; the address and the date stay.

While you write, npm run dev shows the draft at its address in the real folder; anexample of a draft preview is on this workbench. The expected address once published is the one the commands print:/lecture-notes/greenhouse/a-small-example/.

What was and was not shown

The commands changed one source file in a temporary folder. Committing, pushing and deploying are separate steps that none of them take. The preview step is not in the transcript because it depends on whether your dev server is running; the page above shows its result.
